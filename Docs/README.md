# Mritra

**Privacy-preserving detection of money-mule chains that cross banks — built on IBM LinuxONE for the IBM Z Datathon 2026.**

> Each bank alone misses the chain; one all-seeing model is illegal; Mritra recovers most of that gap by exchanging encrypted boundary-account information through an enclave — without any bank's raw data leaving it.

⚠️ **Read first:** all data is **synthetic** (IBM AMLworld). The enclave boundary is **[REAL: IBM Secure Execution | SIMULATED: isolated container — production target IBM Secure Execution]** ← delete one before submission.

---

## The problem

- Cyber-enabled fraud is India's largest money-laundering risk (FATF, 2024).
- Proceeds move through rented mule accounts spread across banks; ~53% of the money leaves a mule account within an hour (RUSI).
- Each bank sees only its own slice, so a chain that crosses banks looks normal to every bank. Pooling data is legally fragile; hashed identifiers are reversible; federated learning shares models, not the missing transactions.

## What Mritra does

1. Each bank computes its own graph and behavioural features and keeps its data.
2. Each round, a bank sends only its **cross-bank transactions** and **boundary-account summaries**, encrypted to the enclave.
3. The enclave on LinuxONE **reconciles** both banks' reports of every transfer, builds the cross-bank graph, computes **network features**, and returns each bank **only its own accounts'** features.
4. Every step is recorded in a **hash-chained transparency log** anyone can verify.

## Reproduce

```bash
git clone <repo> && cd mritra
make setup
# put your Kaggle API token in ~/.kaggle/kaggle.json
make data h1 features train eval    # regenerates every number above
make test                           # privacy, crypto, log and reconciliation tests
make demo                           # 5 banks + enclave + dashboard (docker/podman compose)
```

Hardware used: laptop (Ubuntu 24.04, RTX 4060, 16 GB RAM) for training; IBM LinuxONE (s390x) for the enclave, bank services and Snap ML scoring. See `deploy/linuxone.md`.

## What is and isn't claimed

**Claimed (and tested):** no within-bank transactions, labels or plaintext identifiers leave a bank; banks receive only their own accounts' features; log tampering is detectable; the numbers above are reproducible from the raw data.

**Not claimed:** real bank data; production readiness; formal differential privacy; protection against hardware side channels; hardware attestation (unless marked REAL above); coverage of cash, hawala or trade-based laundering.
